## Как определяется доступ

Доступ зависит от **роли**, **авторства**, **назначения исполнителем** и **статуса задачи**.

| Понятие | Значение |
| :--- | :--- |
| **Администратор** | Пользователь с ролью Administrator. Имеет доступ к задачам команды и управлению участниками. |
| **Участник** | Пользователь с ролью Member. Доступ к задачам определяется назначением исполнителем. |
| **Автор задачи** | Тот, кто создал задачу. Авторство само по себе не даёт участнику права просматривать задачу. |
| **Исполнитель** | Пользователь, которому назначена задача. Исполнителей может быть несколько. |
| **Ответственный администратор** | Администратор, указанный в задаче или проекте. Сейчас это назначение не ограничивает доступ остальных администраторов. |
| **Незакрытая задача** | Задача в статусе New, In progress или In review. |
| **Закрытая задача** | Задача в статусе Done или Cancelled. |

**Ключевое различие:** исполнитель может выполнять задачу, а участник, который одновременно является её автором и исполнителем, может также редактировать её параметры.

## Задачи

| Действие | Администратор | Участник |
| :--- | :--- | :--- |
| Просматривать задачи | Любые задачи команды | Только задачи, где он исполнитель |
| Создавать задачи | Да | Да |
| Выбирать проект при создании | Любой активный проект с действующим ответственным администратором | На тех же условиях |
| Назначать исполнителей при создании | Любых активных пользователей | Тоже любых активных пользователей, не только себя |
| Менять название и описание | У любой незакрытой задачи | Только если одновременно автор и исполнитель |
| Менять дедлайн | У любой незакрытой задачи | Только если одновременно автор и исполнитель |
| Менять приоритет и длительность | У любой незакрытой задачи | Только если одновременно автор и исполнитель |
| Менять проект и исполнителей | У любой незакрытой задачи | Только если одновременно автор и исполнитель |
| Менять ответственных администраторов задачи | Да, у незакрытой задачи | Напрямую — нет |
| Начинать работу — **Start work** | Только если сам исполнитель; задача должна быть New | Если исполнитель; задача должна быть New |
| Отправлять результат на ревью | Только если сам исполнитель; задача должна быть In progress | Если исполнитель; задача должна быть In progress |
| Прикладывать файл к результату | На тех же условиях, что отправка результата | На тех же условиях, что отправка результата |
| Повторно отправлять доработку — **Resubmit for review** | Только если сам исполнитель | Если исполнитель |
| Принимать результат — **Approve** | У любой задачи в In review | Нет |
| Возвращать на доработку — **Request changes** | У любой задачи в In review; комментарий обязателен | Нет |
| Смотреть историю и фидбек | У любых задач | У задач, где он исполнитель |
| Скачивать вложения | У любых задач | У задач, где он исполнитель |
| Отменять незакрытую задачу | Любую | Только если одновременно автор и исполнитель |
| Восстанавливать Cancelled | Любую | Только если одновременно автор и исполнитель |
| Удалять отдельную задачу навсегда | Только задачу в статусе Cancelled | Нет |
| Редактировать или повторно открывать Done | Нет | Нет |

### Путь результата и фидбека

```text
New → In progress → In review → Done
                         │
                         └─ Request changes + комментарий
                                      │
                                      ▼
                                 In progress
                                      │
                              Resubmit for review
                                      │
                                      ▼
                                  In review
```

При возврате исполнитель видит метку **Changes requested**, комментарий, имя администратора и дату. После повторной отправки предыдущий фидбек сохраняется, а все решения доступны в **History**.

### Условия и ограничения

- Результат может содержать текст, ссылку или файл. Лимит файла — **10 МБ**.
- Текст результата и комментарий возврата — до **1 000 символов**.
- После восстановления Cancelled задача становится **New**, текущий результат очищается. История сохраняется.
- Участник не может самостоятельно принять результат или поставить Done.
- Перенос задачи в другой проект меняет её ответственных администраторов на ответственных нового проекта. Это отличается от прямого выбора администраторов, недоступного участнику.

## Проекты

| Действие | Администратор | Участник |
| :--- | :--- | :--- |
| Видеть проекты | Активные и архивные | Все активные проекты |
| Создавать проект | Да | Да |
| Выбирать ответственного при создании | Из активных администраторов | Из активных администраторов |
| Менять ответственных после создания | Да | Нет, даже у созданного им проекта |
| Архивировать проект | Да | Нет |
| Восстанавливать проект из архива | Да | Нет |
| Удалять проект | Да, фактически вместе с его задачами | Нет |
| Менять название и описание существующего проекта | Функция пока не реализована | Функция пока не реализована |

> Создание проекта не повышает роль участника и не даёт ему административных прав на этот проект. Внутри проекта он видит только назначенные ему задачи.

Архивирование проекта само по себе не переводит его задачи в Done или Cancelled.

## Участники и доступ

| Действие | Администратор | Участник |
| :--- | :--- | :--- |
| Открывать **Members** | Да | Нет |
| Видеть корпоративные почты и состояние входа участников | Да | Нет |
| Добавлять профили | Да | Нет |
| Выдавать приглашения | Да, пока вход профиля не активирован | Нет |
| Выдавать новый код приглашения | Да, пока вход профиля не активирован | Нет |
| Отключать пользователя — **Disable** | Да, с защитой последнего активного администратора | Нет |
| Включать отключённого пользователя — **Enable** | Да, если профиль не удалён | Нет |
| Назначать роль Administrator | Да | Нет |
| Снимать роль Administrator | Да, с ограничениями по обязанностям и последнему активному администратору | Нет |
| Удалять участника или администратора — **Delete** | Да, с выбором другого активного администратора для передачи обязанностей | Нет |
| Удалять собственный профиль | Да, если есть другой активный администратор | Нет |

Участник видит **имена и роли активных пользователей в формах назначения**, хотя полноценная вкладка Members и почты ему недоступны.

### Что происходит при удалении пользователя

1. Профиль исчезает из Members, доступ и сессии отзываются.
2. Открытые задачи без другого активного исполнителя передаются выбранному администратору. В совместных задачах остаются другие активные исполнители.
3. Обязанности ответственного администратора передаются там, где иначе не осталось бы другого активного администратора.
4. Задачи, результаты, комментарии и историческое авторство сохраняются.
5. Удалённый профиль нельзя включить обратно через Enable или назначить ему новую работу.

**Disable и Delete работают по-разному:** отключение не передаёт обязанности автоматически, удаление — передаёт при необходимости.

## Вкладки и общие возможности

| Вкладка | Администратор | Участник |
| :--- | :--- | :--- |
| **My tasks** | Его назначенные незакрытые задачи | Его назначенные незакрытые задачи |
| **Due today** | Его незакрытые задачи со сроком сегодня | То же для участника |
| **Overdue** | Его просроченные незакрытые задачи | То же для участника |
| **Projects** | Активные и архивные проекты; любые задачи внутри | Активные проекты; только назначенные ему задачи внутри |
| **All tasks** | Все задачи команды | Недоступна |
| **Archive** | Личный архив назначенных ему Done и Cancelled | Личный архив назначенных ему Done и Cancelled |
| **Cancelled** | Общий список отменённых задач | Отдельная вкладка недоступна; свои отменённые задачи есть в Archive |
| **Members** | Управление пользователями | Недоступна |

Обеим ролям доступны:

- Вход по корпоративной почте и паролю.
- Установка пароля по приглашению и восстановление своего пароля.
- Привязка своего Telegram через **Link Telegram**.
- Автоматический вход при запуске через привязанный Telegram Mini App, если этот способ входа разрешён настройкой приложения.
- Выбор темы **Auto / Light / Night**.
- Фильтры по проекту, статусу, приоритету, длительности и сроку — в пределах соответствующей вкладки и доступных задач.
- Навигация из карточки в историю и обратно через **Back**, **Close** и Escape.

Администратору дополнительно доступен фильтр по исполнителю в общих списках и внутри проекта.

## Важные ограничения

### 1. Автор может потерять доступ к своей задаче

Если участник создаст задачу и назначит только другого человека, сам он перестанет её видеть и редактировать. Авторство без назначения исполнителем сейчас недостаточно.

### 2. Ответственный администратор не ограничивает остальных администраторов

Любой администратор может просматривать и проверять любые задачи команды, даже если не указан ответственным. Разделения прав администраторов по проектам сейчас нет.

### 3. Администратор может принять собственный результат

Запрета на самостоятельную приёмку своей задачи сейчас нет.

### 4. Исполнитель не всегда может менять задачу

Если участник выполняет задачу, созданную другим человеком, он может начать работу и отправить результат. Но менять её название, дедлайн, проект и исполнителей не может.

### 5. Понижение администратора требует передачи обязанностей

Снять роль Administrator нельзя, пока пользователь остаётся ответственным в проектах или задачах, в том числе закрытых. Последнего активного администратора нельзя отключить, понизить или удалить без другого активного администратора.

### 6. Archive всегда личный

Даже у администратора Archive содержит только назначенные ему задачи. Общие закрытые задачи доступны через All tasks, а отменённые — также через Cancelled.

### 7. Свободного обсуждения в задаче пока нет

Отдельного чата или произвольных комментариев нет. Исполнитель отправляет результат, администратор пишет комментарий при возврате на доработку.

## Несоответствие при удалении проекта

> **Важно: текст интерфейса не соответствует фактическому действию.**
>
> Окно подтверждения говорит об удалении пустого проекта. Однако сервер сейчас удаляет проект **вместе со всеми его задачами, результатами, вложениями, ревью и историей**. Это касается и задач Done.
>
> Возможность удалить проект — отдельный путь удаления данных: ограничение «отдельную задачу можно удалить только из Cancelled» его не останавливает.
