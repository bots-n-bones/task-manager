# MVP: Telegram → локальный Supabase

Версия 0.1 от 10 ноября 2026. Узкий первый этап полного SPEC.md.

## Цель

Проверить основной цикл: пользователь создаёт задачу кнопками в личном чате → задача сохраняется в локальном Supabase → появляется в списке пользователя → пользователь добавляет результат и отправляет задачу в `review`.

## Входит в MVP

- Работа бота локально через long polling; домен и вебхук не требуются.
- Идентификация по числовому Telegram ID, регистрация профиля при первом `/start`.
- Для закрытого тестирования — список разрешённых Telegram ID в конфигурации; управление пользователями через бота пока отсутствует. Пустой список не означает открытый доступ.
- Личные сообщения; сообщения групп не обрабатываются.
- Кнопки «Создать задачу», «Мои задачи», «Отмена» и действия в карточке.
- Форма: название → описание (необязательно) → дедлайн (дата) → предпросмотр → сохранить. Автор и единственный исполнитель — текущий пользователь.
- Статусы `new` → `in_progress` → `review`; для `review` обязателен результат текстом или ссылкой.
- Список только своих задач, постраничный вывод и карточка с датой создания, сроком, описанием, статусом и результатом.
- Возврат и отмена формы, понятные ошибки даты и пустых обязательных полей.
- Сохранность данных и незавершённой формы после перезапуска; повторное событие Telegram не создаёт повторную задачу.
- Проверка прав на сервере для каждого действия; нельзя открыть чужую задачу подстановкой ID.

`done` в MVP недоступен. `review` означает «ожидает проверки», а не «выполнено». После добавления администраторов только администратор сможет переводить `review` в `done`; обходного автоматического закрытия нет.

## Минимальная схема

| Таблица | Назначение |
|---|---|
| users | UUID, уникальный Telegram ID, имя, дата регистрации |
| tasks | UUID/номер, автор, единственный исполнитель, название, описание, дата дедлайна, статус, результат, created_at, updated_at, версия |
| bot_sessions | Текущий шаг формы и черновик пользователя |
| processed_updates | Уникальный update_id и состояние обработки для защиты от дублей |

Результат пока хранится в самой задаче. На следующем этапе исполнители и результаты выносятся в отдельные таблицы миграциями без потери данных. Дата создания ставится базой автоматически. Для первого теста используется Europe/Moscow, дедлайн без времени; отправок по сроку ещё нет.

Бот обращается к Supabase с серверным ключом; проверка Telegram ID и принадлежности задачи обязательна в серверной логике. Прямой публичный доступ к таблицам закрыт, RLS включён. Секреты хранятся в `.env`, исключённом из Git.

## Последовательность реализации

1. Локальный Supabase, `.env`, воспроизводимые команды запуска.
2. Миграции минимальной схемы и проверка чтения/записи в базу.
3. Бот: доступ по списку Telegram ID, `/start`, кнопки, создание задачи.
4. Список, карточка, начало работы, результат и отправка в `review`.
5. Проверка основного сценария, прав доступа, дублей и восстановления после перезапуска.

## Приёмка

1. Пользователь из разрешённого списка создаёт задачу кнопками; запись с теми же полями видна в Supabase Studio.
2. После перезапуска задача видна в «Моих задачах»; черновик формы восстанавливается.
3. Второй пользователь не видит её в своём списке и не может прочитать/изменить её по ID.
4. Пустой результат не позволяет установить `review`; текст или ссылка позволяют.
5. Пользователь не может установить `done` ни кнопкой, ни через серверную операцию.
6. Повторная обработка одного события создания не создаёт вторую задачу.
7. При ошибке сохранения бот не сообщает об успехе и сохраняет возможность повторить действие.

## После MVP

1. Администратор Андрей: список всех задач, проверка результата, `review` → `done`, возврат в работу.
2. Проекты, несколько исполнителей, ответственные администраторы, флаги «Важная»/«Быстрая», редактирование и отмена задач.
3. Файлы результата и история изменений.
4. Напоминания в день дедлайна и ежедневная сводка просроченных.
5. Постоянное развёртывание на VPS; отдельная конфигурация и ключи для эксплуатации.
6. Сайт и Mini App, логин/пароль и привязка Telegram.
7. Создание из свободного текста и дополнительные возможности.

Локальный Supabase служит средой разработки. Работа на компьютере не обеспечивает доступность 24/7: после выключения компьютера бот останавливается. Перенос на VPS — отдельный этап, облачный Supabase для MVP не нужен.
